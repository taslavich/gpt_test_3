# TwinBid — Publisher API integration

Полный исходный frontend поверх `TwinBid-publishers-advertisers-v19-source(1).zip`. Контракт сверен с `FProj227.zip`, `docs/publisher/API_MATRIX.md` и соответствующими обработчиками. Backend, RTB, SDK, общая авторизация, роли и рекламодательские исходники не изменены. Подробности интеграции — `PUBLISHER_UI_CHANGES.md`.

## ENV и сборка

Проверено: Node.js 24.19.0, npm 11.9.0. Используйте Node.js LTS 22/24.

В архиве уже настроен единственный файл `.env`. Он используется и при `npm run dev`, и при `npm run build`; создавать или переименовывать ENV-файлы не нужно.

```dotenv
VITE_API_BASE_URL=https://twinbid.io
VITE_USE_MOCK=false
```

Все остальные значения в `.env` также сохранены из рабочего архива. После изменения ENV перезапустите сервер разработки; для production выполните новую сборку.

```sh
npm ci
npx tsc --noEmit -p tsconfig.app.json
npm run lint
npm test -- --run
npm run build
```

Разработка: `npm run dev`; просмотр production: `npm run preview`. Разверните содержимое `dist/` с HTTPS и SPA fallback на `index.html`, включая `/publisher/*`. В существующем backend разрешите CORS-origin фронтенда и заголовки JWT API. Буфер обмена и UUID требуют HTTPS либо localhost. RTB proxy_pass менять не требуется.

## Особенности API

- Источник бизнес-данных — только backend. Загрузка, пустые ответы, ошибки и повтор запроса разделены; ошибки не подменяются нулевыми суммами или демонстрационными таблицами.
- Коды — Popunder с явным Adult/Mainstream, без предвыбранного traffic_type. PATCH отправляет version и опускает неизменённый тип; 409 предлагает обновить объект. IDs/short_code создаёт сервер. Копирование, дублирование, активность, архивирование и диагностика подключены к API.
- Код установки использует public_script_url и short_code сервера: SDK или прежний `/static/adManager.js`. Кабинет не запускает рекламные запросы и не вызывает confirm. Сайты/зоны появляются после реального трафика. Метрики инвентаря — последние 6 месяцев, доход — lifetime.
- Пагинация серверная. В API нет total_count; «Далее» доступна при полной текущей странице. Поиск списков, сортировка и график статистики относятся к текущей странице. В фильтры можно вставлять реальные ID, отсутствующие на первой странице подсказок.
- Статистика поддерживает date/hour/country/device/os/browser/site/zone/ad_code, серверные фильтры и часовые пояса. UTC-период имеет исключительную правую границу. effective_from/effective_to и 1h_utc показываются явно: backend округляет границы до часов. Totals и CTR — серверные за весь период.
- Деньги отображаются точными десятичными строками; сравнение использует BigInt. Number применяется только к координате графика, не к расчёту денег. cumulative_earned/balance/reserved/paid_out/available_for_payout и revenue_status показаны отдельно.
- Выплаты — USDT TRC20/ERC20 и реальные pending/paid/canceled. Минимум $50 подтверждён в `internal/publisher/finance.go`; комиссии не добавлены. Отменяет только оператор. Двойное нажатие объединяется в один POST; неопределённый сетевой результат повторяется с тем же UUID request_id и payload, даже после серверного резерва. Незавершённая операция сохраняется в localStorage отдельно по нормализованному email авторизованного пользователя (он стабилен при существующей смене login id после гидратации /session). Сохраняются только request_id, сумма, сеть, кошелёк, признак отправки и, если уже получен, ID серверной заявки; JWT и пароли в журнал не записываются. После перезагрузки проверяется существующий GET payouts. Текущий DTO не возвращает request_id: равные реквизиты и отсутствие строки на одной странице не доказывают результат. При неоднозначности доступен только повтор того же запроса с прежним UUID. Известный серверный ID позволяет подтвердить заявку через GET без POST. Подтверждённый результат удаляет журнал; сетевые ошибки, таймауты и отказы после неопределённого результата сохраняют его. При недоступном хранилище новый POST блокируется. Одновременная отправка блокируется внутри страницы, а в браузерах с Web Locks — и между вкладками.
- Реквизиты/уведомления сохраняются GET/PATCH settings. Профиль/пароль используют прежние API, язык/тема остаются UI-предпочтениями. Cache изолирован по аккаунту. UI обновляет обзор, баланс и sync-health каждые 30 секунд, не меняя серверную финансовую синхронизацию.

## Версия v2: область изменений и проверки

Изменён только контекст выплат; добавлены `usePublisherPayout.ts`, `publisherPayoutOperation.ts` и тесты восстановления. Страницы, дизайн, переводы, API-клиенты, баланс, статистика, Ad Codes и рекламодательские исходники сохранены.

Исходный `.openai/hosting.json` восстановлен байт-в-байт из v19: `static.directory = dist` и прежний `project_id`. Это конфигурация исходного static-хостинга; новая привязка не создавалась. Публикация и доступность самого внешнего hosting-проекта не проверялись.

Firefox с перехватом HTTP является проверкой браузера и production UI, не live E2E. SDK/ADM/confirm/финансовые цепочки не изменялись и не выдаются за проверенные на живом окружении.
