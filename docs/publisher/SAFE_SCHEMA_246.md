# proj247 — безопасная миграция ClickHouse Loader (схема 248)

В существующей БД `ads.agg_stats` **не удаляются** таблицы, колонки,
проекции и исторические данные. До запуска Loader оператор **вручную** удаляет
`publisher_pop_by_bucket` и четыре старые неключевые колонки:
`pub_user_id`, `ad_code_id`, `zone_id`, `pop_revenue_bucket`.

При старом `ORDER BY` Loader требует, чтобы все четыре колонки уже отсутствовали,
и завершает запуск с ошибкой при несоблюдении условия (ничего не удаляя).
Далее Loader атомарно выполняет `ADD COLUMN IF NOT EXISTS` совместно с
`MODIFY ORDER BY`, задаёт `DEFAULT` и создаёт Publisher-проекцию через
`ADD PROJECTION IF NOT EXISTS`. При полностью обновлённом ключе повторный
`ALTER` не выполняется.

Существующие финансовые MV пересоздаются из актуальных DDL через `DROP VIEW`
/ `CREATE MATERIALIZED VIEW`, **не** через `MODIFY QUERY`.
Источник и таблицы-получатели `TO` и `APPEND TO` не удаляются; денежные строки
не пересчитываются. ClickHouse-refresh задачи сначала останавливаются с
ожиданием завершения активного выполнения, затем отсоединяются производители
фактов, обновляются downstream MV и создаются производители снова.
Независимый hourly POP recovery writer приостанавливается и возобновляется.

Для сохранности данных **все внешние источники записи** в соответствующие
факты, `ortb` и агрегаты должны быть приостановлены на время операции.
Остановка только исполняемого файла Loader не гарантирует отсутствие новых
записей от других сервисов. Не включать запись до успешного завершения DDL.

В старом полном `CreateDB` удалён IPP `DELETE/INSERT` cutover. Полный `CreateDB`
по-прежнему запускается только для пустой базы, а для существующей используется
отдельная безразрушительная миграция. Исторический Publisher POP backfill
не выполняется. Схема маркируется версией **248**, чтобы обновление применилось
даже при наличии предыдущего маркера 246. После успеха последующие рестарты
не пересоздают финансовые MV повторно.

Проверки: `git apply --check`, `go test ./internal/services/clickhouse-loader
./cmd/clickhouse-loader`; живой интеграционный тест требует совместимого
ClickHouse и `PUBLISHER_TEST_CLICKHOUSE_ADDR`.
